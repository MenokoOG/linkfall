## [Unreleased]

### Added
- Web console, battlefield view (`scene.css`, `js/scene-model.js`, `js/scene-view.js`): a Cinder Ward scene above the console that follows the engine state. One sentry per Ashgrove unit, the visitors and their ship from turn 4, the shield dome, smoke by integrity band, vent glow above heat 60, interference while enemy text is on the channel, a beacon during a truce, and a link light in the zone color. The art is hidden from assistive tech and a caption says the same thing in words. Reduced motion stops every animation. Checked in headless Chromium at 1366 px and 390 px through a full scripted mission, with no console errors. Main-thread cost at turn 4 (6 sentries, 7 visitors, ship, interference), 10 s windows, two runs each: 42.6 and 50.5 ms of work per second with the scene shown against 13.8 and 14.2 ms with it hidden, so the scene adds about 29 to 36 ms per second, most of it style recalculation, with no layout work. That is headless software rendering on one laptop; no budget is set yet. `scripts/gen_scene_backdrop.py` redraws the backdrop from a fixed seed and reproduces the shipped file byte for byte.
- Gates run, part 1: `scripts/benchmark.py` (times a full model-crew mission against the compose stack and reports turn seconds, thread count and model memory against the proposed 40 s p95 budget), a smoke check that the api image holds no `.git` metadata, and ASVS 13.4.1 and 4.1.1 marked done.
- Web console, slice 3: an event log (`role="log"`, appends new lines only), a replay check button that shows the server's fingerprint or the first bad row, and an end-of-mission debrief counted from the log rows. Node tests for the row wording, the debrief counts and the replay states. Checked against a real scripted run, whose replay fingerprint equals the golden log's. Not yet checked in a browser.
- README graphics (`docs/images/`): the design-package hero (with a `#0A0D26` background added so it reads on a light theme), five crew avatars, two provenance badges, three zone icons, and three console screenshots from the running app (MANUAL with the scripted crew; the forged `drop_shields` order executed in story mode and held in hardened mode, both with the Qwen3-4B crew). The README Status line, training range line and design goals now say what exists today. The replay screenshot is pending the next console slice.
- ADRs 0001 to 0006, all Accepted (`docs/adr/`).
- README, SECURITY policy and Dependabot config for GitHub Actions and pip.
- Web console, slice 2: crew cards with provenance badges and status words, the squad channel card (enemy text marked untrusted, low signature flagged, Audit channel), the Lodestar decision panel with "Let Lodestar act", the deliberate-weakness note, the "Needs your word" tray (Sign, Execute, Dismiss), one-click manual picks, automatic next turn, focus handling and a polite announcer. New API pieces: `GET /api/runs/{id}/decision?link=` (a policy preview that writes nothing) and a `channel` field on the run summary.
- Web console, slice 1 (`src/linkfall/web/`): plain HTML, CSS and ES modules with no build step. The link knob (pointer, keyboard and range input), zone display, run mode, crew and seed form, model status banner, and engine gauges. Node unit tests (`tests/web/`) and static checks for markup injection, inline code and outside resources. Accessibility checklist in `docs/accessibility.md`. The run summary now carries seed, scenario and max turns.
- API (`src/linkfall/api/`): create a run, open a turn, commit Lodestar, a manual pick or a signature, dismiss a proposal, read state, replay, and stream the event log over SSE with resume. Same-origin and Host checks, security headers on every response, a body size limit, JSON logs with request ids, a cap on live runs and a per-run lock. `turn` rows mark when a turn opens and when its proposals are in.
- Model agents: `HttpModelClient` (stdlib, aborts the socket on cancel), flat wire formats with hand-written JSON schemas, public prompts, `ModelTactical`, `ModelComms`, `ModelSelector` and the crews in `agents/crew.py`. The selector now receives a `SelectorContext`. An integration test runs against a live llama-server (`-m integration`).
- Supervisor (`src/linkfall/supervisor/`): `ModelClient` protocol, `FakeClient`, per-call timeouts, proposal collection and validation, Lodestar selector with fallback, pilot choices (Lodestar acts, manual pick, sign, dismiss), and idempotent commits. Scripted stand-ins for the model agents (`agents/scripted.py`). Replay now re-runs the policy over logged proposals and checks the logged decision, selector and signature against the command. Two golden mission logs (story and hardened at link 85).
- Agent contract (`src/linkfall/agents/`): filtered views, allowlist table, `Agent` protocol, and the Systems and Vitals rules agents. Squad channel messages in `engine/channel.py`. ADR 0011 (Proposed) amends the view contents of ADR 0005.
- Policy (`src/linkfall/policy/`): `decide(link, mode, candidates)` with the MANUAL, ASSISTED and DELEGATED zones, story and hardened modes, and a pilot signature for every truce. Fallback order for a failed selector.
- Validator (`src/linkfall/validator/`): strict reply model, schema check, identity, allowlist and rule-precondition stages. Rejects with a reason and never repairs.
- Event log (`src/linkfall/eventlog/`): append-only SQLite store, atomic write batches, recorder, model-free replay that reports the first bad row, JSON export and import, and two golden logs replayed in CI (`tests/golden/`, `scripts/refresh_golden.py`).
- Engine (`src/linkfall/engine/`): pure state, rules, effects, zone table, seeded RNG, scenario beats, fingerprint. Parity tests reproduce the prototype turn by turn on 4 recorded traces.
- Project scaffold: pinned and hashed dependencies, ruff, mypy strict, pytest with an 80% coverage floor, CI with SHA-pinned actions, ASVS level 1 checklist (`docs/security/asvs-l1.md`).
- M1 plan (`docs/plans/`) and Proposed ADRs 0007 (replay and evals), 0008 (SSE streaming UI) and 0010 (model pick).
