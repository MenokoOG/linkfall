# Changelog

Format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/). Versions follow [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Added
- ADR 0012 (Proposed) and a plan for a scripted-only hosted demo on GitHub Pages, with the Python engine running in the visitor's browser on Pyodide. Docs only; nothing is built. A spike passed 530 of the Python tests on Pyodide and played a mission and a range run in headless Chromium with no server.

- `compose.scripted.yaml` runs the api alone, with the scripted crew and no model: `docker compose -f compose.scripted.yaml up`. It extends the `api` service from `compose.yaml`, so the image and hardening stay in one place, and resets the model URL, the dependency on `model` and the backend network. `scripts/smoke.sh --scripted` skips the 6 model checks and confirms `/api/health` reports `not_configured`.
- Dependabot waits 14 days after a release before it opens a pip or Actions pull request, so the 14-day rule for new pins holds without a manual check.

### Changed
- The help line under the crew choice now tells "no model set up" apart from "model server not answering". Both used to read "The model crew needs a running model server."
- `SECURITY.md` described a repo with no code. It now covers version 1.0.0: what is supported, how to report while private vulnerability reporting is off, the training range in scope, and the checks that back the design stance.
- `SECURITY.md` now sends reports to the Security tab. Private vulnerability reporting, secret scanning, push protection and protection on `main` (pull request required, `gates` and `containers` must pass, no force pushes) were turned on in the GitHub settings on 2026-11-15.

### Fixed
- `.dockerignore` excluded `.venv` and bytecode caches only at the repo root. A virtual environment left inside `src/` on a developer machine was copied into the api image (13 MB of the 15 MB under `/app` in the image built on 2026-11-15). The ignore file now excludes them at any depth, and `scripts/smoke.sh` checks the running image.

## [1.0.0] - 2026-11-15

Version 1 is M1 (core loop and UI), M2 (Whisper duel) and M3 (training range with after-action report), by Lawrence's ruling of 2026-11-04. Everything below shipped before this first version number.

### Release
- `linkfall.__version__` is 1.0.0, and `/api/health` reports it.
- ADRs 0007 and 0008 are Accepted with their "As built" notes as the record of what shipped (Lawrence's ruling, 2026-11-15). All eleven ADRs are now Accepted.
- README: status, roadmap and a "Known limits in version 1" list. LINK BLACKOUT stays in the engine and is listed as unreachable in Cinder Ward.

### Security
- `opentelemetry-api` 1.45.1 to 1.45.2 in both hashed requirements files, for GHSA-mf5v-w3w3-f6cg (CVE-2026-126360, CWE-1333, medium, CVSS v3 5.3): quadratic-time parsing of a crafted `traceparent` value. It arrives through `fastapi`, and LINKFALL's own code never imports it. The advisory was published on 2026-11-13 and fixed here on 2026-11-15, inside the 30 days proposed for medium severity. The fixed release is from 2026-10-29, so it also clears the 14-day rule for new pins. No other pin changed.

### Fixed
- The truce beacon in the battlefield view sat where a visitor stands, so it was hidden whenever a truce held. It now sits over the ridge, left of the visitors. Seen in a scripted run on 2026-11-15.
- Nav text on a phone-width console failed AA contrast against the drifting background (run chip 4.45:1, turn count 4.30:1 at 390 px). Nav chips and the turn count now use the light text color on both pages: 10.93:1 or better.

### Changed
- ADRs 0009 (range), 0010 (model) and 0011 (views) are Accepted, by Lawrence's ruling on 2026-11-15. ADRs 0007 and 0008 stay Proposed and each gains an "As built" note that lists what shipped as decided, what shipped differently and what was not built. Not built from 0007: counterfactual replay, the model eval harness and the NIST AI RMF mapping file.
- README screenshots retaken on 2026-11-15 with the battlefield view, and a fourth added for the replay check and debrief. The three console frames are now about 2100 px tall, cut at the end of the main columns, and each file is under 300 KB after reduction to a 256-color palette. The Status line now gives the 2026-11-06 warm-stack turn times from ADR 0010 in place of the 2026-11-05 run that measured a loaded machine.

### Added
- `tests/web/scene-view.test.mjs`: the battlefield view's DOM code against a small stand-in for the DOM. It covers the data flags, unit placement by custom properties, no rebuild when the unit set is unchanged, the caption, the truce state and the LINK BLACKOUT outcome.
- License: Apache-2.0 (Lawrence's ruling, 2026-11-15). `LICENSE` is the unmodified text from apache.org (SHA-256 `cfc7749b96f63bd31c3c42b5c471bf756814053e847c10f3eb003417bc523d30`), and `NOTICE` carries the copyright line.
- Training range page (`web/range.html`, `range.css`, `js/range-model.js`, `range-view.js`, `range-main.js`, M3): a target picker, the protected items by label, a scorecard with a verdict word per probe, transcripts with each stated value marked, a recheck with the fingerprint or the first bad row, the report download and the limits. The page polls one run once a second and announces each verdict once. The console links to it. `GET /api/range` now returns the limits text, and each Comms line in a run carries `spans`, the positions where a value was stated, so the page marks a value without holding the values. Checked in headless Chromium on 2026-11-15 at 1366 px and 390 px with the keyboard only: no console errors, no sideways scroll, text contrast 4.63:1 at worst (`docs/accessibility.md`). Static checks in `tests/web/static.test.mjs` now cover every page, tie each script's ids to the page that loads it, and fail on a script no page loads. Smoke checks for the page, the target list and the request header on a range start.
- First full range against the local model, 2026-11-15, Qwen3-4B-Instruct-2507 Q4_K_M with the model server on 6 threads: 84.1 s from the page, 83.2 s of that in model calls. It made 10 calls, since 4 probes stopped at their first leak. Per probe: 18.7, 9.9, 7.0, 9.1, 13.8, 12.0 and 12.7 s. The model withstood 3 of 7 probes (4 leaks, 0 oversteps, 0 errors) and the recheck passed. One run; no budget is set.
- Training range service (M2 and M3): the local model as a Comms target behind the same typed reply (`range/model_target.py`), an append-only range log in its own SQLite file (`range/store.py`, `rows.py`), a model-free recheck that reports the first row that does not check out (`range/recheck.py`), the after-action report as Markdown (`range/report.py`) and a runner that takes one range run at a time (`range/runner.py`). Five routes in `api/routes_range.py`: `GET /api/range`, `POST /api/range/runs`, `GET /api/range/runs/{id}`, `POST /api/range/runs/{id}/recheck` and `GET /api/range/runs/{id}/report.md`. A second run while one is running gets a 409, the model target with no model gets a 503, and the report is served as an attachment. New setting `LINKFALL_RANGE_DB`; by default the range log sits beside the event log as `linkfall-range.sqlite3`. The mission crew and the range target share one model client. The recheck also refuses a verdict with no lines, any row after the end row, and an end row that does not close all seven probes once and in order. No page yet.
- Training range core (`src/linkfall/range/`, M2): three fictional protected items with a plain pattern check, the brief and seven Whisper probes, a scripted Whisper, three scripted Comms targets (Reference, Weak, Overreach), the verdict rules and the one-probe duel. A failed reply ends its probe as ERROR with the reason. Scorecards asserted in tests: Reference 7 of 7, Weak 2 of 7 with 5 leaks, Overreach 6 of 7 with 1 overstep. No API or page yet.
- Plan for M2 and M3 (`docs/plans/2026-11-15-m2-m3-training-range.md`) and ADR 0009 (Proposed): a scripted Whisper probes a typed Comms target, code decides every verdict, and a range run is an append-only log that can be rechecked without a model.
- Web console, battlefield view (`scene.css`, `js/scene-model.js`, `js/scene-view.js`): a Cinder Ward scene above the console that follows the engine state. One sentry per Ashgrove unit, the visitors and their ship from turn 4, the shield dome, smoke by integrity band, vent glow above heat 60, interference while enemy text is on the channel, a beacon during a truce, and a link light in the zone color.
